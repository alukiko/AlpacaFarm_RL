# Frozen local judge decisions

`local_judge_cpu_base.jsonl` contains one judgment for each of the first 200
standard four-vote majority pairs ordered by the SHA-256 pair ID. The pair
selection does not use model outputs or human-majority direction. The displayed
answer order is balanced deterministically by the first hex digit of the pair
ID. `local_judge_cpu_swap.jsonl` repeats the first 50 pairs with reversed
answer order to test position sensitivity. `local_judge_cpu_repeat.jsonl`
reruns the same 50 pairs in their original displayed order to measure
same-prompt variability. All three files are generated by
[`scripts/run_local_judge.py`](../../scripts/run_local_judge.py).

The evaluator is a local **Qwen3 4B Instruct 2507 Q4_K_M** model in Ollama
0.40.16, model ID `0edcdef34593`, blob SHA-256
`85e4a5b7b8ef0e48af0e8658f5aaab9c2324c76c1641493f4d1e25fce54b18b9`.
Temperature is zero, seed 42, context size 4096, and output cap 24 tokens.
`num_gpu=0` forces CPU inference; `ollama ps` reported 100% CPU. The model
runner's observed working set was approximately 5.24 GB, below the 8 GB
project limit. The prompt and response-format schema are fixed in the script.

The individual records retain response text, aligned choice, prompt and output
token counts, elapsed time, and settings. The model judgments are frozen inputs
for the short control run. `python scripts/run_analysis.py` does **not** call
Ollama, any paid API, or an external network service.

These predictions are from Qwen3, **not** the published `alpaca_eval_gpt4`
judge; they must not be pooled or attributed to that judge. The answers in the
underlying AlpacaFarm human file are public research data under CC BY-NC 4.0.
