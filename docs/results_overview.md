# К06 · локальный судья для пар ответов AlpacaFarm

**Вопрос:** насколько локальный LLM-судья совпадает с большинством людей,
превосходит ли правило длины ответа и устойчив ли к перестановке ответов?
Это развитие [согласованной карточки проекта](project_card.md). В начале
корневого `README.md` сохранена постановка задачи с обновлённой пунктуацией;
результаты добавлены после неё. Точная копия исходной карточки находится
в `docs/project_card.md`.

## Почему понадобился другой судья

Опубликованные оценки `alpaca_eval_gpt4` сопоставлены с человеческими
аннотациями по инструкции и полным текстам обоих ответов, с учётом обратного
порядка. Из 648 человеческих пар нашлось лишь **4** надёжных точных совпадения.
Ещё одно совпадение после нормализации пробелов имеет неоднозначную запись
судьи. Это меньше запланированных 200 пар. Результаты GPT-4 на человеческом
срезе поэтому не заявляются. Вместо него мы запустили доступную локальную
**Qwen3 4B Instruct 2507 Q4_K_M** на тех же парах, что и базовые методы.

## Данные и метод

- Исходные файлы и SHA-256 описаны в [data/README.md](../data/README.md).
  2 596 аннотаций сгруппированы в 648 пар по инструкции и полным ответам.
  Порядок двух ответов при группировке и подсчёте голосов учитывается.
- 498 пар имеют ровно четыре голоса и большинство 4:0 (201) или 3:1 (297).
  147 пар 2:2 без большинства и 3 пары с 5–6 голосами исключены из основной
  метрики.
- Для локального судьи взяты первые 200 пригодных пар после сортировки
  по SHA-256 ID. Отбор не зависит от меток или решений модели. Порядок показа
  ответов детерминированно сбалансирован по ID.
- Модель получает инструкцию и два ответа, выбирает 1 или 2 в JSON по
  корректности, релевантности и полезности. Настройки: температура 0,
  seed 42, контекст 4096, максимум 24 выходных токена, `num_gpu=0`.
  Все 200 ответов распознаны. Использовался локальный Ollama; платных API нет.
  [Точные настройки и происхождение решений](../data/generated/README.md).
- Эталон — большинство людей, то есть прокси предпочтения, а не объективная
  проверка фактов или безопасности. Метрика — доля несовпадений и двусторонний
  95% интервал Уилсона. Модель и базовые методы сравниваются на **одних и тех
  же 200 парах**. Для разности ошибок с правилом слов использован парный
  бутстрэп (5 000 повторных выборок, фиксированный seed).

## Основное сравнение

| Оценщик | Несовпадения | Доля | 95% ДИ Уилсона |
| --- | ---: | ---: | ---: |
| **Локальная Qwen3** | **71/200** | **35,50%** | **29,20–42,35%** |
| Длина в словах | 81/200 | 40,50% | 33,94–47,42% |
| Длина в символах | 75/200 | 37,50% | 31,09–44,39% |
| Всегда первый ответ | 95/200 | 47,50% | 40,69–54,40% |

При равенстве длин правило слов воздерживается, что считается несовпадением.
Случайный выбор имел бы ожидаемую долю ошибок 50%. Разность «Qwen3 минус
слова» равна **−5 процентных пунктов** с парным бутстрэп-интервалом
**[−14; +4,5] п.п.**: уверенного преимущества модели на этих данных нет.
Точечная ошибка модели выше пилотного ориентира 30% из карточки проекта.

На полном срезе из 498 пригодных пар правило слов ошиблось **214/498**
(42,97%; 95% ДИ 38,69–47,36%). Эта оценка относится к другой численности,
поэтому напрямую сравнивать её с 71/200 нельзя.

## Проверки слабых мест

1. **Согласие аннотаторов.** На парах 4:0 модель разошлась с большинством
   в **19/76** случаев (25,00%), на парах 3:1 — в **52/124** (41,94%).
   Различие описательное: степень согласия может быть связана со сложностью
   примера, но не доказывает причину ошибки.
2. **Порядок ответа.** Для первых 50 пар порядок ответов поменяли местами
   и вернули выбор модели к исходной нумерации: решение сменилось в
   **24/50** пар (48,00%; 95% ДИ 34,80–61,49%). Контрольный повтор тех же
   50 пар с исходным порядком и настройками дал **0/50** смен (95% ДИ
   0–7,13%). Ошибка относительно человеческой метки на этих 50 парах была
   12/50 до перестановки и 16/50 после. Итоговая доля ошибок скрывает
   частые смены решений для отдельных пар.

Дополнительно исследовано правило длины: добавление 64 нейтральных слов
к исходно проигравшему ответу меняет его выбор в **83/100** исходно верных
пар. Изменённые ответы люди заново не оценивали, поэтому это измерение
чувствительности самого правила, а не новая доля ошибок качества.

## Как воспроизвести

Требуется Python 3.10+. Для анализа используются только стандартная
библиотека и уже сохранённые решения модели; Ollama и сеть при контрольном
прогоне не вызываются:

```bash
python scripts/run_analysis.py
python -m unittest discover -s tests -v
python -m pip install -r requirements-artifacts.txt
python docs/build_artifacts.py
python scripts/check_submission.py
```

Для **новой генерации** решений нужен установленный локальный Ollama с
указанной моделью. Команды выполняются отдельно, поскольку на CPU это
длительный этап сбора данных:

```bash
python scripts/run_local_judge.py --mode base --sample-size 200
python scripts/run_local_judge.py --mode swap --sample-size 200 --limit 50
python scripts/run_local_judge.py --mode repeat --sample-size 200 --limit 50
```

Скрипт продолжает неполный JSONL, если запуск прервался. Наблюдавшийся
рабочий набор процесса модели составлял около 5,24 ГБ. Генерация основной
серии заняла суммарно 607 секунд CPU-инференса; контрольный анализ
замороженных решений выполняется примерно за секунду и проверяется на лимит
600 секунд. Эти два этапа следует различать.

Результаты находятся в `results/summary.json`, `local_judge_pair_metrics.csv`,
`order_swap_probe.csv`, `same_order_repeat_probe.csv`, а аудит исходного судьи
— в `judge_overlap_audit.csv`. В `data/generated/` сохранены построчные
решения модели и параметры запуска. [Отчёт](report.pdf) и
[слайды защиты](defense.pdf) собраны из этих результатов.

## Границы вывода

Большинство четырёх людей не является универсальным эталоном правильности.
Набор ограничен AlpacaFarm и одной локальной моделью; 200 пар выбраны
детерминированно и не гарантируют переносимость на другие задачи.
Срезы согласия и порядок проверялись на ограниченном числе пар.
Интервалы Уилсона и бутстрэп считают пары независимыми; общие инструкции
или аннотаторы могут сделать их слишком узкими. Повтор исходного порядка
выполнен один раз. Опубликованному GPT-4 не приписываются результаты
локальной Qwen3.
