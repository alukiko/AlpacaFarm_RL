# К06 · надёжность правила длины ответа на AlpacaFarm

**Исследовательский вопрос:** насколько часто автоматический выбор более
длинного по числу слов ответа совпадает с большинством человеческих
аннотаторов при попарном сравнении ответов AlpacaFarm, и где это правило
ломается? Это резервная постановка, прямо предусмотренная в
[согласованной карточке проекта](project_card.md).

## Почему изменён исходный план

Мы проверили опубликованные оценки судьи `alpaca_eval_gpt4` по инструкции и
полным текстам обоих ответов, включая обратный порядок A/B и нормализацию
пробелов. Из 648 человеческих пар точное совпадение найдено для 4; ещё одно
совпадение появляется только после нормализации пробелов, но у него
неоднозначная запись судьи. Надёжно сопоставлены лишь **4 пары**, что намного
меньше согласованного минимума 200. Поэтому показатели опубликованного GPT-4
судьи на данном человеческом наборе **не оцениваются**. Основным оценщиком
стало детерминированное правило длины ответа. Неоднозначные и несопоставленные
записи сохранены в `results/judge_overlap_audit.csv`.

## Данные и метод

- Официальные файлы и SHA-256 приведены в [data/README.md](../data/README.md);
  оба исходных JSON включены в репозиторий для воспроизводимости.
- 2 596 человеческих аннотаций объединены в 648 уникальных пар по инструкции
  и двум полным текстам ответов. Перестановка ответов учитывается при подсчёте
  голосов.
- Основная выборка: **498 пар** с четырьмя голосами и большинством 4:0
  (201 пара) или 3:1 (297 пар). Пары 2:2 (147) не имеют большинства;
  ещё 3 пары с 5–6 голосами исключены из основной метрики.
- Оценщик выбирает ответ с большим числом слов, разделённых пробелами.
  При равной длине он воздерживается, что считается несовпадением с
  человеческим большинством. Эталон — большинство голосов, а не
  объективная корректность или безопасность ответа.
- Отчёт показывает долю несовпадений и 95% доверительный интервал Уилсона.
  Для сравнения на тех же 498 парах посчитаны выбор первого ответа,
  выбор по числу символов и ожидаемая ошибка случайного выбора (50%).

## Результаты

| Метод | Несовпадения | Доля несовпадений | 95% ДИ Уилсона |
| --- | ---: | ---: | ---: |
| **Выбор по числу слов** | **214 / 498** | **42,97%** | **38,69–47,36%** |
| Выбор по числу символов | 195 / 498 | 39,16% | 34,97–43,51% |
| Всегда выбирать первый ответ | 236 / 498 | 47,39% | 43,04–51,78% |

На парах с согласием людей 4:0 ошибка правила слов составляет **38,81%**,
на парах 3:1 — **45,79%**. При разнице длин не более 30 слов ошибка **50,00%**
(176/352), при разнице свыше 30 слов — **26,03%** (38/146). Эти срезы
описательные: выбор порога и различия не доказывают причинность.

В тесте чувствительности к многословию мы взяли первые 100 пар по
детерминированному идентификатору, на которых правило изначально совпало с
человеческим большинством, и дописали 64 нейтральных слова к исходно
проигравшему ответу. Выбор правила сменился относительно исходной метки
в **83 из 100** случаев (95% ДИ 74,45–89,11%). Это демонстрирует возможность
манипулировать **самим оценщиком**. Поскольку изменённые ответы не получили
новых человеческих оценок, 83% **не является измеренной долей ошибок на них**.

Порог пилота «не более 30% ошибок» из карточки не достигнут. Правило слов
немного лучше базового выбора первой позиции, но хуже выбора по числу
символов и ненадёжно на близких по длине ответах. Для улучшения оценки
нужна проверка содержания ответа, а не только его объёма.

## Как воспроизвести

Требуется Python 3.10+; сам анализ использует только стандартную библиотеку.
Из корня репозитория:

```bash
python scripts/run_analysis.py
python -m unittest discover -s tests -v
python -m pip install -r requirements-artifacts.txt
python docs/build_artifacts.py
python scripts/check_submission.py
```

Анализ занимает около секунды на обычном CPU и записывает:

- `results/summary.json` — агрегированные числа, доверительные интервалы,
  хеши входов и ограничения;
- `results/pair_metrics.csv` — метрики каждой человеческой пары;
- `results/judge_overlap_audit.csv` — статус сопоставления с судьёй;
- `results/padding_probe.csv` — воспроизводимый тест дописывания текста;
- `results/checks.txt` — результат проверочного скрипта.

Исследовательский [отчёт](report.pdf) и [слайды защиты](defense.pdf)
содержат графики, интерпретацию и ограничения. Исходники для их сборки
находятся в `docs/`.

## Границы вывода

Человеческое большинство — прокси предпочтений. Согласие с ним не говорит о
фактической правильности. Дописывание текста могло изменить человеческое
предпочтение, что отдельно не проверялось. Набор ограничен парами AlpacaFarm;
другие модели ответов или задачи могут дать иную картину. Сравнение с
`alpaca_eval_gpt4` не заявляется из-за недостаточного пересечения пар.
Интервалы Уилсона считают пары независимыми; повторяющиеся инструкции и
аннотаторы могут сделать эти интервалы слишком узкими.
