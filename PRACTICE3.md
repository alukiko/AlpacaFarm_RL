# Практика 3: командный аудит оценщика, К06

Это отдельное командное домашнее задание по направлению `labeling`. Материалы находятся в ветке `k06-practice3-team`. Исходная карточка трёхнедельного проекта сохранена в [README.md](README.md); результаты того проекта находятся в другой ветке `complete-k06-project` и не являются человеческой разметкой для П3.

## Что подготовлено

- `audit/slice.jsonl`: 52 разных пары ответов на запросы, 20 с `group="core"` и 32 с `group="second"`. В объекте только запрос и оба ответа, без опубликованных человеческих меток.
- `audit/instruction.md`: правила независимого попарного сравнения, версия 1.0.
- `audit/annotations.csv` с назначениями для A1, A2 и A3. По инструкции каждый независимо размечает все 20 объектов `core` и минимум 4 объекта `second`. В К06 каждому назначено по 8 объектов `second`, всего по 28 пар.
- [Форма разметки К06](https://docs.google.com/forms/d/e/1FAIpQLSfQ36CeQiOqW-1leHPKIF5mLolUDa-CPmRrGe6Em1KGMiZ8kQ/viewform). После выбора фамилии открываются все 28 назначенных пар с полями для метки и времени в секундах.
- `personal_annotations/AU_annotations.csv`, `VO_annotations.csv`, `AD_annotations.csv`: отдельные рабочие листы A1, A2 и A3 по 28 строк. Они находятся внутри проекта для удобства; для итоговой сдачи нужен объединённый `audit/annotations.csv`.
- `audit/baseline_predictions.csv` и `audit/probe_results.csv`: шаблоны того же ноутбука. Результаты заполняются после независимой разметки.
- `scripts/annotate.py`: локальный просмотр назначенных пар в порядке из `annotations.csv` с записью своей метки и времени.

Команда К06 относится к дорожке A: в основном проекте уже есть собственный локальный оценщик Qwen3. Вне общей ветки подготовлены его решения для 52 объектов, отдельные оценки ассистента, базовая линия и два зонда (порядок ответов и связь с длиной). Они не являются ответами участников команды и будут доступны для сравнения после того, как каждый участник завершит свою разметку. Поскольку все трое участников размечают пары, для строгого соблюдения требования скрытого оценщика файл `scorer.jsonl` нужно передать куратору или другому человеку, который не участвует в разметке, до начала работы.

## Откуда взяты пары

Источник: [`tatsu-lab/alpaca_eval`, конфигурация `alpaca_farm_human_crossannotations`](https://huggingface.co/datasets/tatsu-lab/alpaca_eval), лицензия CC BY-NC 4.0. Скрипт `scripts/prepare_slice.py` воспроизводимо объединяет четыре опубликованные оценки каждой пары, учитывая обратный порядок двух ответов, выбирает пары с большинством 3:1 или 4:0, сортирует их по хешу полных текстов и берёт позиции 201–252. В командный `slice.jsonl` попадают только тексты и новые ID `K06-P3-001`–`K06-P3-052`. Позиции выбраны за пределами первых 200 пар, использованных в основном эксперименте; метки исходного датасета в ветку не копируются.

## Как работать втроём

1. Прочитать `audit/instruction.md`. Первые десять объектов `core` использовать как проверку понятности правил. Эти суждения входят в общий объём разметки. Если правила потребуется уточнить, зафиксировать версию 1.1 до продолжения работы.
2. В `notebooks/` заполнены три копии выданного `03_Блокнот_студента.ipynb`. Файл `K06_AU_lab3_student.ipynb` соответствует A1, `K06_VO_lab3_student.ipynb` соответствует A2, `K06_AD_lab3_student.ipynb` соответствует A3. В примере преподавателя вместо инициалов в имени файла указан псевдоним, например `K06_A1_lab3_student.ipynb`. Настройки команды во всех копиях заданы как `TEAM_ID="K06"`, `DIRECTION="labeling"`, `ANNOTATOR_IDS=["A1", "A2", "A3"]` и `PAIRWISE_TASK=True`. По заданию решения вносятся в `EDIT HERE`, затем сохраняется вывод встроенных тестов. В каждой копии сохранён результат 11 из 11.
3. Каждый участник самостоятельно заполняет форму по своей фамилии. Если удобнее работать локально, участник A1 начинает командой `python scripts/annotate.py --annotator A1 --audit-dir audit --annotations-file personal_annotations/AU_annotations.csv --pilot-only`. Участники A2 и A3 подставляют свой псевдоним и путь к файлу. Программа остановится после первых 10 объектов `core`. После проверки ясности правил участник возобновляет работу без `--pilot-only`. Если инструкция обновлена, при возобновлении добавляет `--instruction-version 1.1`. До сохранения всех своих оценок участники не обсуждают конкретные решения и не смотрят чужие.
4. Перенести ответы участников из таблицы формы в личные CSV по псевдониму и ID пары. Заполняются `label` (`A`, `B`, `TIE` или `SKIP`) и `elapsed_seconds` (положительное число секунд). Строки с префиксом «ТЕСТ К06» пропустить. Если инструкция менялась, проставить `instruction_version=1.1` для суждений после обновления. После заполнения всех трёх личных CSV запустить команду объединения ниже. Скрипт перенесёт метки, время и версии инструкции в общий `audit/annotations.csv`, сохранив ID, псевдонимы и порядок показа. После объединения пропустите ячейку генерации шаблонов, чтобы сохранить заполненный файл.
5. После завершения разметки заполнить `baseline_predictions.csv` по всем 52 ID. В `probe_results.csv` добавить минимум два зонда для дорожки A. К06 использует перестановку A/B и сравнение с длиной ответов. Для каждого зонда записываются `probe`, положительное целое `n`, `metric`, численное `value` и краткое `interpretation`. Теперь можно открыть решения оценщика, сравнить их с независимыми человеческими метками и добавить `scorer.jsonl` в `audit/`. Для каждого ID в нём одна запись с полем `verdict`.

## Команды проверки

Запускать из корня `AlpacaFarm_RL_practice3`. Перед разметкой можно проверить подготовленный комплект.

```powershell
python scripts/check_p3.py --phase prepared
```

После заполнения всех трёх личных CSV собрать их и проверить готовый комплект с базовой линией, зондами и файлом оценщика.

```powershell
python scripts/merge_annotations.py --team-audit-dir audit --personal-dir personal_annotations
python scripts/check_p3.py --phase final
```
