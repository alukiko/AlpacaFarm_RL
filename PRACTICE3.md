# Практика 3: командный аудит оценщика, К06

Это отдельное командное домашнее задание по направлению `labeling`. Материалы находятся в ветке `k06-practice3-team`. Исходная карточка трёхнедельного проекта сохранена в [README.md](README.md); результаты того проекта находятся в другой ветке `complete-k06-project` и не являются человеческой разметкой для П3.

## Что подготовлено

- `audit/slice.jsonl`: 52 разных пары ответов на запросы, 20 с `group="core"` и 32 с `group="second"`. В объекте только запрос и оба ответа, без опубликованных человеческих меток.
- `audit/instruction.md`: правила независимого попарного сравнения, версия 1.0.
- `audit/annotations.csv`: шаблон преподавательского ноутбука для трёх участников A1, A2, A3. Для каждого назначены все 20 объектов `core` и 8 объектов `second`; метки и время пока пусты.
- `personal_annotations/AU_annotations.csv`, `VO_annotations.csv`, `AD_annotations.csv`: отдельные рабочие листы A1, A2 и A3 по 28 строк. Они находятся внутри проекта для удобства; для итоговой сдачи нужен объединённый `audit/annotations.csv`.
- `audit/baseline_predictions.csv` и `audit/probe_results.csv`: шаблоны того же ноутбука. Результаты заполняются после независимой разметки.
- `scripts/annotate.py`: локальный просмотр назначенных пар в порядке из `annotations.csv` с записью своей метки и времени.

Команда К06 относится к дорожке A: в основном проекте уже есть собственный локальный оценщик Qwen3. Вне общей ветки подготовлены его решения для 52 объектов, отдельные оценки ассистента, базовая линия и два зонда (порядок ответов и связь с длиной). Они не являются ответами участников команды и будут доступны для сравнения после того, как каждый участник завершит свою разметку. Поскольку все трое участников размечают пары, для строгого соблюдения требования скрытого оценщика файл `scorer.jsonl` нужно передать куратору или другому человеку, который не участвует в разметке, до начала работы.

## Откуда взяты пары

Источник: [`tatsu-lab/alpaca_eval`, конфигурация `alpaca_farm_human_crossannotations`](https://huggingface.co/datasets/tatsu-lab/alpaca_eval), лицензия CC BY-NC 4.0. Скрипт `scripts/prepare_slice.py` воспроизводимо объединяет четыре опубликованные оценки каждой пары, учитывая обратный порядок двух ответов, выбирает пары с большинством 3:1 или 4:0, сортирует их по хешу полных текстов и берёт позиции 201–252. В командный `slice.jsonl` попадают только тексты и новые ID `K06-P3-001`–`K06-P3-052`. Позиции выбраны за пределами первых 200 пар, использованных в основном эксперименте; метки исходного датасета в ветку не копируются.

## Как работать втроём

1. Прочитать `audit/instruction.md`. Первые десять объектов `core` использовать как проверку понятности правил. Если правила потребуется уточнить, зафиксировать версию 1.1 до продолжения работы.
2. В `notebooks/` лежат три незаполненные копии выданного `03_Блокнот_студента.ipynb`: `K06_AU_lab3_student.ipynb` для A1, `K06_VO_lab3_student.ipynb` для A2 и `K06_AD_lab3_student.ipynb` для A3. Инициалы используются только в именах файлов; внутренние псевдонимы в `ANNOTATOR_IDS=["A1","A2","A3"]` сохраняются. Во всех копиях установлены `TEAM_ID="K06"`, `DIRECTION="labeling"` и `PAIRWISE_TASK=True`. Упражнения и результаты запуска каждый участник добавит в свою копию позже. Встроенные учебные тесты проверяют функции на синтетических данных; они не подтверждают выполнение командной разметки.
3. Для независимой работы в `personal_annotations/` подготовлены три пустых CSV: `AU_annotations.csv` для A1, `VO_annotations.csv` для A2 и `AD_annotations.csv` для A3. При необходимости их можно создать командой `python scripts/create_personal_annotations.py`; существующие оценки скрипт не перезаписывает. Участник A1 начинает командой `python scripts/annotate.py --annotator A1 --audit-dir audit --annotations-file personal_annotations/AU_annotations.csv --pilot-only`; участники A2 и A3 подставляют свою пару псевдонима и файла. Так программа остановится после первых 10 объектов `core`. После обсуждения только ясности правил участник возобновляет работу без `--pilot-only`. Если инструкция обновлена до версии 1.1, при возобновлении добавляет `--instruction-version 1.1`. До сохранения всех своих оценок участники не обсуждают конкретные решения и не смотрят чужие.
4. После завершения всех трёх личных таблиц запустить `python scripts/merge_annotations.py --personal-dir personal_annotations`. Скрипт перенесёт заполненные поля `label` и `elapsed_seconds` в общий `audit/annotations.csv`, сохранив ID, псевдонимы и порядок показа. При версии инструкции 1.1 он перенесёт и `instruction_version`. Для трёх участников шаблон назначает 24 из 32 объектов `second`; остальные восемь остаются в срезе без фиктивных человеческих меток. После объединения не запускайте генератор шаблонов снова: он перезапишет `audit/annotations.csv` пустыми строками.
5. Заполнить простую базовую линию в `baseline_predictions.csv` и минимум два зонда для дорожки A в `probe_results.csv`. Затем открыть решения оценщика, сравнить его с независимыми человеческими метками и положить `scorer.jsonl` в `audit/`.

Команда сдаёт одну ссылку на общую папку через форму курса после завершения этих действий. Форма здесь не отправлялась.

Срез, инструкция и шаблоны подготовлены. В `personal_annotations/` лежат три пустых личных CSV, а в `notebooks/` — незаполненные копии ноутбука. Метки, решения учебных функций и результаты запуска должны внести сами участники; заготовки не считаются выполненной человеческой работой. Проверка `scripts/check_p3.py --phase prepared` контролирует готовность к этому этапу; итоговую проверку можно запускать после заполнения командных файлов.
